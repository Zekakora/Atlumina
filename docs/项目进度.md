## 三、 阶段 1：数据层（已完成）

- **模型**：`PhotoRecord`（完整 EXIF 字段 + GPS + 星级 + 标签）、`FolderRecord`、`SmartAlbum`、`LibraryFilter`（文件夹/相机/评分/标签，JSON 序列化）、`TagRecord`
- **SQLite**（`PhotoDatabase`，WAL）：照片/文件夹/智能相册/标签(Tags+PhotoTags) 表；幂等 upsert；多条件查询 `QueryPhotosAsync(folder,camera,rating,tag)`；目录计数、相机计数、标签计数

## 五、 关键决策与踩坑记录（Agent 必读）

1. **MetadataExtractor 2.9.3 API 与常见版本不同**：
   - 类名是 `ExifSubIfdDirectory` / `ExifIfd0Directory`（不是 `ExifSubIFDDirectory`）
   - tag 常量在基类 `ExifDirectoryBase`（`TagIsoEquivalent`、`TagDateTimeOriginal` 等）
   - 日期用扩展方法 `DirectoryExtensions.TryGetDateTime(dir, TagDateTimeOriginal, out dt)`（无 `TryGetDateTimeOriginal`）
   - 数值可能返回 `UInt16/UInt32`，需显式转换（`ToInt`）
   - `GeoLocation` 是 **struct**，`GetGeoLocation()` 返回 `GeoLocation?`，取 `.Value.Latitude`
   - **ARW 有多个 SubIFD**，拍摄数据在第二个 → 跨目录合并取值
2. **WIC/WinRT（Windows.Graphics.Imaging）**：
   - `BitmapDecoder.GetPreviewAsync()` 取 RAW 内置预览（快），`GetThumbnailAsync()` 取小图
   - WinRT 投影**无 WebP 编码器**（只有解码器）→ L2 用 JPEG
   - `GetSoftwareBitmapAsync` 支持 `BitmapTransform` 缩放 + `ExifOrientationMode`
   - `BitmapTransform.Rotation` 的 `ScaledWidth/Height` 是**旋转前**尺寸，90/270 输出会交换（实现见 `DecodeScaledAsync`）
   - RAW 预览 JPEG 不带方向标签 → 必须用 `PhotoRecord.Orientation` 手动旋转
3. **打包运行（重要）**：winapp CLI 无法为 loose-layout 清单注入 WinAppSDK 框架依赖 → 运行时 `<Module>` 初始化抛 `0x80040154 类未注册`。**解法：自包含 + unpackaged**（`WindowsPackageType=None`），`dotnet run` 直接跑 exe，不依赖 winapp/框架包
4. **CommunityToolkit**：`RelayCommand<T>` 收到 XAML 字符串参数（`CommandParameter="1"`）会抛异常 → 用 `RelayCommand<object?>` 自行解析；非泛型 `RelayCommand` 构造只收无参 `Action`
5. **WinUI 3 无公开 `Cursor` 属性**（`UIElement.ProtectedCursor` 是 protected）
6. **TreeViewItem 缩进内部固定**（`TreeViewItemTemplateSettings.Indentation` 非公开）→ 自定义紧凑模板 `Styles/TreeView.xaml` + `IndentScale` 转换器缩放 35%
7. **SQLite `LIKE ... ESCAPE '\'` 会转义 Windows 路径反斜杠** → 直接 `LIKE 'path\%'` 不用 ESCAPE
8. **缩略图缓存一致性**：`ThumbnailCachePath` 必须位于当前缓存目录，否则会复用陈旧文件（`MainPageViewModel.IsInCacheDirectory` 校验）；工具缓存目录 `{dbdir}\cache\thumbs` 与应用 `AppPaths` 一致
9. **运行前**：残留 `MyAlbum.App` 进程会锁 DLL 导致构建失败（先 `Stop-Process`）
10. **应用启动**：unpackaged 应用 DB 在 `%LOCALAPPDATA%\MyAlbum\myalbum.db`，缓存 `...\cache\thumbs`；崩溃日志 `%TEMP%\MyAlbum\crash.log`
11. **SQLite 列序**：`ALTER TABLE ADD COLUMN` 会把新列加在末尾（存量库与新库列序不同）→ 读 `SELECT *` 时用 `GetOrdinal(列名)`，勿硬编码索引
12. **隐藏文件夹**：`Folders.IsHidden`，查询/计数统一追加 `HiddenFolderExclusion` SQL 片段（排除隐藏目录及其子目录），树构建跳过隐藏目录
13. **SqliteParameterCollection 复用命令**：同一 `SqliteCommand` 循环里反复 `AddWithValue("$path", ...)` 会**追加**同名参数而非替换，再次执行报 `Must add values for the following parameters` → 批量写入前必须先 `cmd.Parameters.Clear()` 再绑定
14. **导入性能（几万张 ARW/HIF/JPG）**：
    - 根因 ① UI 线程阻塞：`ScanFolderAsync` 从 UI 线程调用，`await SemaphoreSlim.WaitAsync()` 在信号量空闲时**同步完成不切线程**，导致目录枚举+排序和每个文件的同步 EXIF 解析全在 UI 线程 → 界面冻结
    - 根因 ② `ThumbnailService` 全局 `SemaphoreSlim(1,1)` 把所有 WIC 解码**串行**；③ 逐条独立事务写库；④ 每文件一次 `Progress.Report` 数万次 post 塞满 UI 队列
    - 解法：枚举 `Task.Run` + `Parallel.ForEachAsync`（并发=min(CPU核,8)）+ 缩略图改 per-path `ConcurrentDictionary<string,Lazy<Task>>` 去重（不同文件并行、同文件共享）+ `BulkUpsertPhotosAsync` 500 条/事务 + 进度节流 100ms + 轻量指纹查询（不再 `SELECT *`）
15. **WinUI 3 `ProgressBar` 的 `Maximum` 默认是 100**（不是 1）：`Value` 绑定 0..1 的分数只走 1%（进度条看着不动，文字却正常）→ 设 `Maximum="1"` 或把值 ×100
16. **构建偶发假错误**：`CS2001 找不到 GeneratedMSBuildEditorConfig.editorconfig` / `WMC9999 未将对象引用设置到实例` 都是 obj 陈旧/竞态导致，非代码问题 → 删 `obj`+`bin` 后重新 `dotnet build` 即恢复
17. **Supercluster 聚合计数**：`map` 返回 `{cluster:false, photo:p}` 时 seed 无 `count` 字段，`reduce: acc.count++` 第一次即 `undefined++`=**NaN**，聚合图标尺寸/数字全 NaN → 标记渲染不出来（看着像"没聚合"）。**正确做法**：直接用 supercluster 原生 `f.properties.point_count`，无需自定义 reduce；若要自研 `count` 需在 `map` 里 seed `count:1`（seed 已含中心点，reduce 只对剩余点 +1，勿双数）
18. **C#→WebView2 的 JSON 大小写**：`JsonSerializer.Serialize` 默认输出 PascalCase（`"Lat"/"Lon"/"Id"`），而 `map.html` 里读的是小写 `p.lat/p.lon/p.id/p.thumb` → 坐标全 `undefined`，`supercluster.load` 静默失败，**地图一张照片都不显示**。必须 `JsonSerializerOptions { PropertyNamingPolicy = JsonNamingPolicy.CamelCase }`（`MapViewModel.MarkerJson`）。反向 JS→C# 的 `postMessage` 用 `JsonObject` 按名读不受影响
19. **MSBuild 节点偶发崩溃**：`MSB4166 子节点过早退出` / `CS0234 找不到 Microsoft.UI.Color` 均为 MSBuild 多进程节点崩溃/obj 损坏的**级联假错误**（本机内存吃紧时频发）→ `-m:1` 单节点 + 删 obj/bin 重建即可；0 错误即通过
20. **WebView2 首帧消息竞态**：`host.Navigate()` 后立即 `PostWebMessageAsJson` 会被静默丢弃（页面 JS 的 `message` 监听器还没注册）→ 必须等文档加载完成再推。`MapPage` 用 `TaskCompletionSource` + `NavigationCompleted` 把 `EnsureMapLoadedAsync` 变成"等加载完才返回"，再推照片；不要依赖 `NavigationCompleted` 事件兜底双推（会重复 fitBounds）
17. **阶段 3 新增：WebView2 虚拟主机**：`SetVirtualHostNameToFolderMapping` 只能映射**本地目录**（HTML 里的相对资源 + `https://myalbum.data/...` 图片 URL 都可用），解决 file:// 限制；Leaflet/Supercluster 已**本地捆绑**（`Assets/Map/`），离线也加载 JS，仅瓦片需联网
18. **阶段 3 新增：`ScrollViewer.MinZoomFactor` 崩溃**：XAML 设 `< 0.1` 会 `ArgumentException`（WinUI 强制下限 0.1），且 XAML 属性解析偶发失败 → 在代码后台设置（`0.1f`），勿放 XAML

- **YuNet 输入格式**：必须 **raw [0,255] + BGR 通道顺序**（OpenCV `blobFromImage` 默认 `scalefactor=1.0`、不 swapRB）。一旦 `/255` 归一化 → **obj 分支恒 0** → `sqrt(cls*obj)` 全 0 → 检测全挂；用 RGB 通道顺序 → 坐标错乱。这是本次最大的坑：测试 `obj_8 max=0.000` 与 `0.996` 的差别只在输入是否 /255

- **bbox 解码**：`cx=(c + bbox[0]) * stride`（**c 是网格列，不是 c+0.5**）、`w=exp(bbox[2])*stride`；landmark `(kps[2n]+c)*stride`
- **插值字符串里嵌 `{x:0.1}` 会把浮点格式化成诡异值**（显示 3791 实为 379.1）→ 调试用 `x.ToString("F1")` 存局部变量

**需求**：去重工具的组改为「**文件名相同（去掉扩展名）+ 所在目录**」归组——同一目录下 ARW+HIF+JPG 算一张逻辑照片；同名文件跨多个文件夹视为重复。悬停照片组可查看每个文件完整路径。用户给出建议保留思路：组内格式最丰富 + 路径最正常有序（例：同名文件在 2026-01-01/sub/	emp，因存在日期归类夹 → 保留日期夹，删 sub/temp）。

   - 平手再比**总字节数**（更接近原始）→ **最新修改**

## 三十九、2026-08-09 会话备忘（修复：GpsPlace 列序错位导致主页无照片/切换闪退）

**用户反馈**：加完 GpsPlace 之后主页没照片，切换页面卡死闪退。

**根因（踩坑 #11 复发）**：ALTER TABLE ADD COLUMN 永远把新列追加到**末尾**，但新增列时 CREATE TABLE 里把 GpsPlace 放在了**中间**（GpsAltitude 之后）→ 存量库（走 ALTER，GpsPlace 在末尾）与新建库（GpsPlace 在中间）列序不一致 → ReadPhoto 按位置顺序读取全部错位（GpsPlace 读到 Artist 的值、Artist 读到 Description…），网格数据全乱 → 主页空白、翻页/预览访问错乱字段抛异常闪退。

**修复**：把 GpsPlace 从 CREATE TABLE 中间移到**末尾**（DeepAnalyzedAtUtc 之后），ReadPhoto 相应地把 GpsPlace = GetNullableString 移到最后读取。这样新建库（CREATE 末尾）与存量库（ALTER 末尾）列序完全一致。

**验证**：新增 --migratetest：用原始 SQL 建「无 GpsPlace 的旧库」→ 插一行 → 经 PhotoDatabase 初始化跑 ALTER → 读取字段全部对齐（kind/iso/尺寸/GPS 正确，place 为空）；真实库 --dump 31 张全字段正常；dotnet build MyAlbum.slnx -c Debug -m:1 0 警告 0 错误。

**教训**：新增列必须**只追加到末尾**（CREATE TABLE 与 ALTER 都放末尾），绝不能插中间——否则存量库与新建库列序分裂。

## 四十四、2026-08-10 会话备忘（打包后地图无 WebView 修复：user data folder + CsWinRT 重载名坑）

**用户反馈**：IDE（bin\Debug）运行地图正常，打包安装到 `C:\Program Files\Atlumina` 后地图显示「没有 WebView」。

**根因（两个叠加）：**
1. **unpackaged WebView2 用户数据目录默认在 exe 所在目录**：MapHostService 原代码直接 EnsureCoreWebView2Async()（无 user data folder）。IDE 跑在可写的 bin\Debug 没问题；装到 Program Files 后普通用户对该目录无写权限 → CoreWebView2 环境创建失败 → 地图页初始化失败。证据：bin\Debug 下出现了 MyAlbum.App.exe.WebView2\EBWebView（默认数据目录就在 exe 旁）。
2. **CsWinRT 投影的重载名陷阱**：WinUI 3 用 winmd + CsWinRT 源生成，Microsoft.Web.WebView2.Core.winmd（1.0.3719.77）里带 userDataFolder 的静态方法叫 **CreateWithOptionsAsync(browserExecutableFolder, userDataFolder, options)**，**不是** CreateAsync（后者只有无参 CreateAsync()）。直接写 CreateAsync(null, folder) 或 CreateAsync(null, folder, opts) 都报 CS1501 无此重载（被 WMC9999 掩盖成 XAML 假错误，删 obj 后才露出真因）。

**修复**（MapHostService.InitializeAsync）：
`csharp
var userDataFolder = Path.Combine(AppPaths.AppDataDirectory, "WebView2");
var environment = await CoreWebView2Environment.CreateWithOptionsAsync(
    null, userDataFolder, new CoreWebView2EnvironmentOptions());
await webView.EnsureCoreWebView2Async(environment);
`
把 WebView2 用户数据显式指到 %LOCALAPPDATA%\Atlumina\WebView2（始终可写），与 DB/缩略图/模型同根，卸载零迁移。MapPage 与 GpsToolPage 共用 MapHostService，一处修复两处生效。

**踩坑记录（新增）**：
- 反编译 winmd 确认重载用 ilspycmd -t <FullTypeName> <winmd>（dotnet tool install -g ilspycmd）
- WMC9999「未将对象引用设置到实例」在这里是 CS1501 编译错误被 XAML 编译器掩盖的假象，删 obj/bin 全量重建后露出真实错误
- 判断「IDE 正常/安装异常」的 WebView2 类问题，先查 exe 旁是否出现 *.exe.WebView2 目录——有即证明在用默认数据目录

## 四十六、2026-08-11 补记（闪退根因 + 已修复项）

**闪退背景（用户补充）**：不是启动崩溃，而是「主页 → 手动点开地图页 → 地图页加载完 → 点回主页」时闪退。栈指向 RebuildGridRows 的 GridSource.Clear() → ObservableCollection.OnCollectionChanged → COM 0x80004005。

**根因**：主页 Frame 默认 NavigationCacheMode=Disabled → 每次返回主页重建页面 → OnNavigatedTo 重新 wait InitializeAsync() 全量重载 3 万张 → 在返回的布局间隙 Clear+重建 GridSource 触发 COM 竞态。

**已修复**：
1. HomeViewModel.InitializeAsync 加 _initialized 幂等守卫 → 返回主页不再全量重载
2. RebuildGridRows 改回**同步打包**（去掉 wait Task.Run）：纯算术几十 ms，消除 Clear/Add 间的 await 竞态
3. HomePage.OnNavigatedTo 加 try/catch 容错，导航往返异常不致白屏
4. 优化 5（并行初始化）、优化 7（首屏分批渲染）因引入该 COM 竞态**已回退**

**保留生效的优化**：优化 1（去掉逐张 File.Exists，已回退版本仍保留内部 GetOrCreate 的 File.Exists 兜底）、优化 2（轻量投影查询 QueryGridPhotosAsync + ReadGridPhoto，网格/人像/地点查询不再拉 BLOB 列）。

**注意**：_initialized 守卫意味着从地图页返回时不会自动刷新（依赖 watcher 的 LibraryChanged 或手动刷新按钮）。
